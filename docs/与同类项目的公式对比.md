# 与同类项目的公式对比

本文记录我们把工业公式与其它开源实现逐条对过的结果。
目的有两个：**发现自己的错误**，以及**记住别人的错误**（照抄会算错）。

对比对象：

| 项目 | 技术栈 | 定位 |
|---|---|---|
| [LakMoore/EveAssemblyLine](https://github.com/LakMoore/EveAssemblyLine) | TypeScript / Next.js | 工业规划**模拟器**（多角色槽位排程、库存账本、回收、压缩、发明） |
| [Nareya79/eve-omni](https://github.com/Nareya79/eve-omni) | Electron / JS | 一体化助手（覆盖层、贸易、采矿、导航、工业、PI…） |

---

## 一、核对结果：我们错了两处（已修）

### 1. 反应改装件的加成被完全忽略 ❌ → 已修

反应改装件的时间/材料减免写在属性 **2713 / 2714** 上，
而我们只认 2593 / 2594 / 2595，于是**反应改装件一点效果都没算进去**。

逐个对照 SDE 的 `typeDogma` 后确认（8 个反应改装件全部只带 2713/2714）：

| 类型 | 名称 | 实际带的属性 |
|---|---|---|
| 46484 / 46485 | 屹立中型复合反应堆时间效率 I / II | 2713 = −20 / −24 |
| 46486 / 46487 | 屹立中型复合反应堆材料效率 I / II | 2714 = −2 / −2.4 |
| 46496 / 46497 | 屹立大型反应堆效率 I / II | 2713 = −20/−24，2714 = −2/−2.4 |

**为什么会漏**：`industryModifierSources.jsonl` 为这些改装件声明的是
**2715–2720**（按反应类型细分），但那些属性在物品上一个值都没有 ——
是遗留声明。导入器只导入「被声明引用」的属性，于是真正带值的 2713/2714 从未进库。
**教训：以物品实际携带的属性为准，不要以声明表为准。**

修复后：`46484 → 时间 ×0.80`（此前是 ×1.00），00 里再乘 2357=1.1 → ×0.78。

### 2. 拷贝 / 发明的「时间减免技能」根本不存在 ❌ → 已修

我们原先写的是「实验室运作理论 3406 + 高级实验室运作理论 24624 = 5% + 3%」，
来源是社区数值。核对 SDE 后：

| 技能 | 效果属性 | 真实效果 |
|---|---|---|
| 3406 实验室运作理论 | attr **471** `laboratorySlotsBonus` | **+1 槽位**，不减时间 |
| 24624 高级实验室运作理论 | attr **471** `laboratorySlotsBonus` | **+1 槽位**，不减时间 |
| 45748 反应效率 | attr 2661 `reactionSlotBonus` | +1 槽位 |

也就是说拷贝与发明**没有任何技能能缩短时间**；只有「高级工业理论」因为其属性
（attr **1961**）写着「a bonus to **all industry job times**」而适用。

原表会把拷贝/发明时间低估约 **25%**（`0.75 × 0.85 = 0.6375`，应为 `0.85`）。

> **方法上的教训**：技能效果不该抄攻略，应该读技能自己的效果属性 ——
> 那是机制的定义（`tests/test_formulas.py::SkillAndRigAttributeTests` 现在钉住了这一条）。

## 二、别人的错误：不要照抄

| # | 他们的做法 | 事实 | 照抄的后果 |
|---|---|---|---|
| 1 | `facilityBonuses.ts` 把 **2601 当成时间**、**2602 当成费用** | SDE 属性名：2601 = `strEngCostBonus`（**费用**）、2602 = `strEngTimeBonus`（**时间**） | 时间与费用倍率对调。**我们是对的**（`test_structure_attributes_are_not_swapped` 钉住） |
| 2 | 反应时间只用 Reactions 技能，**不含高级工业理论** | attr 1961 的描述是「a bonus to **all industry job times**」 | 反应时间偏大 15%（5 级时）。**我们原来是对的** |
| 3 | 拷贝 / 发明的技能时间系数恒为 1 | 高级工业理论适用于所有工业任务 | 拷贝/发明时间偏大 15% |
| 4 | 材料两处取整：`ceil(base×runs×(1−ME/100))` 后再乘设施倍率再 `ceil` | 见下节「待确认」 | 每条材料最多多算 1 个 |
| 5 | 多条材料改装件只取**最小值**（最优的一条），不是连乘 | EVE 里多个改装件效果叠加 | 装两条材料改装件时材料偏大（约 3.8%） |
| 6 | 高安/低安分界用 `security >= 0.5` | CCP 的定义是**高安 ≥ 0.45**（0.45–0.49 的星系仍算高安） | 0.45–0.49 星系里改装件减免少算近一半 |
| 7 | 解密器识别靠「是否存在属性 1124」，无日志 | 若某个解密器缺 1124 会被静默丢弃 | 静默算错发明概率 |

> 第 1 条特别值得记：他们的代码读起来完全正常，错在**属性 ID 与语义的绑定**上。
> 这正是我们坚持「从 SDE 读属性**名字**再判断语义」而不是靠注释/记忆的原因。

## 三、我们一致的部分（说明公式骨架没问题）

| 项 | 两边 |
|---|---|
| 材料公式骨架 | `max(runs, ceil(base × runs × (1 − ME/100) × 设施倍率))` ✓ |
| 反应不吃 ME / TE | ✓ |
| 结构倍率属性 | 2600 材料 / 2601 费用 / 2602 时间 / 2721 反应时间 ✓（语义一致，尽管他们变量名写反） |
| 改装件属性 | 2593 时间 / 2594 材料 / 2595 费用 ✓ |
| 安等倍率来源 | 都从**改装件自身**的 2355/2356/2357 读，缺省 1.0 ✓ |
| 技能是相乘 | `Π(1 − 每级减免 × 等级)` ✓ |
| 制造吃 TE、反应不吃 | ✓ |
| 安装费基数 | 制造/反应 = EIV；拷贝/发明 = 2%×EIV；研究 = 2%×EIV×秒/105 —— **他们没有实现**这部分 |
| 蓝图 rank 属性 | 1955 —— **他们没有实现** |

## 六、待确认（记录在案，不猜）

1. **材料取整的位置**：他们在乘设施倍率**之前**取整一次，我们是最后取整一次。
   两者最多差 1 个单位/条，且只在「ME 调整后仍带小数」时出现。
   我们暂按单次取整实现（`tests/test_formulas.py::test_ceil_rounding_vectors` 有实测向量），
   但**没有权威资料能排除两段取整**。若将来能拿到确定证据，再改。
2. **attr 1982 `manufactureTimePerLevel`（−1%/级）**：蓝图制造活动所要求的科研技能
   也会减少该蓝图的制造时间。我们尚未纳入（上限约 −5%）。
3. **发明产出的期望值处理**：他们把计划产出压到需求上限（发明固有的超产盈余不入账），
   并在设计文档里写「覆盖 120%」而代码实现的是 95% 二项置信 —— 文档与代码不一致。
   我们若实现发明，应采用「二项置信 + 明确展示期望/最坏情况」的口径。
4. **T2/科学技能的制造时间减免**（同第 2 条）与**植入体加成**：都未纳入。

## 七、从 eve-omni 采纳的两点

| 做法 | 我们怎么落地 |
|---|---|
| **在说明里逐项解释「为什么要这个权限」** | 我们的 scope 表（`app/config.py` 的 `SCOPE_TIERS` + `scope_audit_report()`）逐项给出「用途 / 档位 / 需要什么条件」，并说明我们**不**申请 send_/write_/open_window 这类「能代替你做事」的权限 |
| **在 Release 说明里列 SHA-256**（项目没有代码签名） | 每个 Release 都列出便携包的 SHA-256，并在 README 里给出 `Get-FileHash` 的核对方法 |

> 另外它请求了 `esi-ui.open_window.v1` / `esi-ui.write_waypoint.v1`
> 并注明「on click only」—— 这从侧面验证了我们审计函数的判定：
> 这两个确实属于「能代替你做事」的权限，只是他们的功能需要，而我们不需要。
